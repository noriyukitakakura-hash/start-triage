# バイタルの実測モード（呼吸数・CRT・脈拍・意識）

- 文書バージョン: 0.3 / 2026-11-22（胸郭の契約の機械検査を追加）
- 関連: `SPEC.md` §2.2, §2.3, §2.4, §3.3, §3.4, §4.4, §5.3

---

## 1. なぜ実測するのか

現場の START 法では呼吸数は数値で与えられない。傷病者の胸郭の動きを**見て数える**。
数値提示（`呼吸 32 回/分`）は閾値の暗記訓練にはなるが、現場で必要な
「見て判断する」技能を一切訓練できない。

そこで利用者が**自分で計測する実測モード**を設ける。対象は4つ。

| 項目 | 現場の手技 | アプリでの再現 |
|---|---|---|
| 呼吸数 | 胸郭の動きを見て数える | 傷病者イラストの胸郭が呼吸数どおりに動く。タップで数える |
| CRT | 爪床を5秒圧迫し、離して色が戻るまでを数える | 指のモデルを押し続け、離してから色が戻る時間を自分で測る |
| 橈骨動脈 | 手首に触れて拍動の有無を確かめる | 触知点が脈拍どおりに拍動する。**触知不能なら一切動かない** |
| 意識（指示応答） | 声をかけ、反応から従命の可否を判断する | 声かけを選んで吹き出しの反応を読む。**反応があることと従命できることは違う** |

設定は1つにまとめてある。「現場を再現するか否か」という一つの軸であり、
項目ごとに切り替える必要がない。

### 実測化で得られるもの

| 得られるもの | 内容 |
|---|---|
| 無呼吸の自然な提示 | **「胸郭が全く動かない」という現場そのままの手がかり**になる。`自発呼吸: なし` というテキストラベルの人工性が消える |
| 死戦期呼吸の認識 | 呼吸数 4〜9 回/分を、数えるのではなく**見てわかるパターン**として提示できる |
| 反応と従命の区別 | うめき声や払いのけは**反応だが従命ではない**。START法ではいずれも I類（赤）であり、`指示応答: 従えない` という一行では決して訓練できない |
| 技能の分離採点 | 計数精度と区分判定を分けて採点でき、「数え値は 2 回ずれたが 30 回以上という判断は正しい」というフィードバックが返せる |

## 2. 設計の前提: 観察時間と分解能

観察して数える場合、判別できる分解能は観察時間で決まる。

| 観察時間 | 分解能 | 29 と 30 を判別できるか |
|---|---|---|
| 6 秒 × 10 | 10 回/分 | 不可 |
| 10 秒 × 6 | 6 回/分 | 不可 |
| 15 秒 × 4 | 4 回/分 | 不可 |
| 30 秒 × 2 | 2 回/分 | 不可 |
| 60 秒 | 1 回/分 | 可（ただし 1 回数え間違えると区分が反転する） |

**±1 の真の境界値（9/10・29/30）と実測は両立しない。**
1 症例に 60 秒必要となり、10 問チャレンジが純粋な計数作業 10 分になる上、
タイム計測が「数える忍耐」の測定に変質する。

### 結論: 2 つのモードは異なる技能を担う

| モード | 訓練する技能 | 呼吸数の提示 | 境界値 |
|---|---|---|---|
| **実測モード**（**既定**） | 現場の実務（見て「明らかに速い」と判断する） | アニメーション + タップ計数 | 循環・意識のみで使う |
| **数値モード** | 閾値の正確な記憶（9/10・29/30 の線引き） | 数値 | 呼吸数・循環・意識で使う |

どちらも必要な技能であり、片方が他方を代替しない。

> **既定は実測モード。** 現場で必要なのは「見て判断する」技能であり、
> 何も設定しない利用者がそれを訓練できる状態にする。
>
> 副作用として、**既定では呼吸数の境界値（9/10・29/30）が出題されない**。
> 実測モードは閾値から4以上離す制約があるため（次項）。
> 閾値そのものを覚えたい場合は設定で数値モードへ切り替える。

### CRT にも同じ限界がある

CRT の閾値は 2.0 秒。目視での計測誤差は人間の反応時間からおよそ ±0.3 秒あり、
**1.9 秒と 2.0 秒は区別できない。** 呼吸数と同じく閾値から離す。

| 帯 | 数値モード | 実測モード（margin 0.5 秒） |
|---|---|---|
| 通過 | 1.0–1.9 秒 | **1.0–1.5 秒** |
| 該当（I類） | 2.0–4.0 秒 | **2.5–4.0 秒** |

帯の間に 1.0 秒の差があり、目視誤差 ±0.3 秒では区分が反転しない。

### 実測モードでは境界値の概念が成立しない

境界値症例とは、呼吸数が 9/10・29/30、CRT が 1.9/2.0 ちょうどの症例を指す。
**呼吸数と CRT の両方にマージンが入ると、どのステップも境界値を取れなくなる。**

> 歩行と気道確保は真偽値判定なので元から境界値を持たない。
> 意識も真偽値で、境界値と呼んでいたのは「通過した呼吸数・CRT が境界値である」ことだった。
> 両方にマージンが入るとこれも成立しない。

したがって **実測モードの10問セットは境界値 0 問になる。** これを異常としない。
閾値そのものを覚える訓練は数値モードが担う。

### 判別マージン ±4 の根拠

実測モードでは呼吸数を判定閾値から **4 回以上**離す（`rrMargin = 4`）。
JP-FDMA（下限 9・上限 30）での値域は次のとおり。

| 帯 | 数値モード | 実測モード | 15 秒観察時の呼吸回数 |
|---|---|---|---|
| 該当（下限）→ I類 | 4–9 | **4–5** | 1.00 – 1.25 回 |
| 通過 | 10–29 | **14–25** | 3.50 – 6.25 回 |
| 該当（上限）→ I類 | 30–44 | **34–44** | 8.50 – 11.00 回 |

15 秒の観察で 3 帯が明確に分離し、**帯の間に 1 回以上の差がある**ため、
数え間違いが 1 回あっても区分が反転しない。

歩行可能な症例（III類）の軽症域も通過域との交差を取り、マージンを尊重する（14–20 回/分）。
歩行可能なら呼吸数は評価されないが、実測モードでは利用者が胸郭の動きを見てしまうため、
**どの症例であれ閾値付近の曖昧な値を提示してはならない。**

## 3. 実装上の必須事項

### 3.1 気道確保ボタンの存在が答えを漏らしてはならない

数値モードの仕様（SPEC §2.2）は「**自発呼吸なしの症例のみ**、回答前に気道確保ボタンを挟む」。
数値モードでは `呼吸数 0` が同時に表示されるため問題ないが、
実測モードでは**ボタンの有無が観察前に無呼吸であることを教えてしまう。**

→ **実測モードでは全症例に気道確保ボタンを表示する。**
自発呼吸がある症例で押した場合は「自発呼吸を確認。気道確保は不要」と返し、判定は変えない。
漏洩がなくなり、かつ実際の START 法の手順（呼吸を確認し、なければ気道確保）に忠実になる。

### 3.2 アニメーションは厳密に毎分 `respiratoryRate` 回でなければならない

利用者のタップ数が真の呼吸数と一致しなければ、**誤った数値を教えることになる。**

CSS `animation-duration: ${breathCycleSeconds(rr)}s` で駆動する。

- コンポジタ駆動のため周期が正確
- メインスレッドを占有せず、10 問モードの `performance.now()` 計測を妨げない
- `breathCycleSeconds(rr) × rr === 60` をテストで保証している

### 3.3 死戦期呼吸の不規則化は平均レートを保つこと

死戦期呼吸は不規則な喘ぎと長い休止で表現する必要があるが、
**不規則化しても平均レートは厳密に `rr` を保たなければならない。**

→ 1 ループに `GASPS_PER_LOOP`（= 3）回の呼吸を不均等な間隔で配置し、
ループ長を `GASPS_PER_LOOP × breathCycleSeconds(rr)` 秒とする。
これにより見た目は不規則でも平均レートは厳密に `rr` になる。

### 3.4 CRT は圧迫時間を満たさなければ測定を成立させない

現場の手技は爪床を5秒間圧迫する。圧迫が足りなければ毛細血管が十分に空にならず、
**正しく測れない。**

→ 5秒未満で離した計測は無効として扱い、やり直させる。
手技の要点をここで体で覚えてもらう。

#### 残り秒数は押している指に隠れる

読み取り欄は図のすぐ下にある。スマートフォンで爪を押すと、
**押している指とその付け根が読み取り欄を覆ってしまい、残り秒数が読めない。**
指は接触点より下に伸びるため、下へ動かしても解決しない。

→ **圧迫中の残り秒数だけをセルの上辺より外へ絶対配置する。**
セルの外に出すので高さは増えず、スクロールも生まれない。
圧迫中以外は従来どおり読み取り欄に収める（3セルの骨格は変えない）。

読み上げ領域は**同じ要素のまま位置だけを変える**。要素ごと差し替えると
live region が作り直され、読み上げが落ちることがある。
また残り秒数は読み取りであって操作ではないため `pointer-events-none` とし、
下に重なる声かけボタンへのタップを奪わない。

### 3.5 脈拍の視覚化で判定に効くのは「触知可否」

JP-FDMA の循環評価は **CRT ≧2秒 または 橈骨動脈 触知不能**。
**脈拍数は判定に使わない参考値**である。

→ 触知不能の症例は**一切動かさない**。無呼吸の胸郭が全く動かないのと同じ構造で、
静止そのものが手がかりになる。静止した触知点に拍動を示す色を使わないのも同じ理由。

脈拍数のタップ計数は現実性のために用意するが、回答の前提条件にしない。
計数の数理は呼吸と共通（`domain/tapCounting.ts`）。

### 3.6 低呼吸数と無呼吸の判別

呼吸数 4〜5 回/分は 12〜15 秒に 1 回しか動かず、**計数では無呼吸と区別できない。**

→ **死戦期呼吸のパターン（深く不規則な喘ぎと長い休止）で判別させる。**
「動きがあるか／全くないか」が判断基準であり、これが現場の実技そのものである。
学習モードの解説で `explain.agonalNote` により明示的に補足する。

### 3.7 アクセシビリティ（必須）

動きだけで情報を伝えるのは WCAG 違反（SPEC §5.3）。

→ `prefers-reduced-motion: reduce` の場合、その症例の呼吸数提示を
**自動的に数値へフォールバック**し、フォールバックしたことを画面に表示する
（`observation.reducedMotionFallback`）。支援技術向けには常に数値を DOM に持たせる。

### 3.8 タイムの比較可能性

観察時間が支配的になるため、実測モードのタイムは数値モードと比較できない。

→ 自己ベストを**提示方式ごとに分けて保持**する（`bestTimeMs: { numeric, observed }`）。

さらに **X への投稿は実測モードの全問正解に限る**（SPEC §2.5）。
数値を読むだけの数値モードはタイムが短く、現場で必要な技能も示さない。
共有される記録を現場寄りの技能に揃えるため、投稿の入口を実測モードだけにする。
投稿文にもモードを明記する。

自己ベストの記録自体は両モードで行う。投稿の可否とは別の話として扱う。

---

### 3.9 声かけが答えを漏らしてはならない

- **押すまで反応を出さない。** 先に見せては、確かめる行為そのものが訓練にならない。
- **声かけボタンは症例によらず常に3つ出す。** 出し分けると、選択肢の構成が
  反応の種類を漏らしてしまう（気道確保ボタンと同じ理屈、§3.1）。
- **無呼吸の症例は「声のみ」の反応を持たない。** 呼吸が無いのに発声するのは
  生理学的に矛盾し、かつ利用者を混乱させる。生成側の整合性制約で保証する。
- 吹き出しとボタンは**胸郭より上下の空白に置く**。胸郭を覆えば呼吸の計数ができなくなる。
  実寸（390×680 / 844×390）の目視で、立位・臥位の双方について確認する。

## 4. 呼吸パターン

`domain/breathing.ts` の `breathingPatternOf()` が分類する。
パターンは**見た目の分類**であり、トリアージ判定の基準値とは別概念である
（判定は必ず `judge()` が `RuleProfile` で行う）。

| パターン | 条件 | 見た目 | 振幅 `--breath-amp` |
|---|---|---|---|
| `apneic` | 自発呼吸なし | **全く動かない**（静止そのものが手がかり） | アニメーションなし |
| `agonal` | 1–9 回/分 | 深く不規則な喘ぎ + 長い休止 | 1.18 |
| `normal` | 10–29 回/分 | 規則的 | 1.12 |
| `rapidShallow` | 30 回/分以上 | 浅く速い | 1.06 |

> **振幅は生理学的な胸郭の変位より誇張してある。**
> 実際の呼吸による胸郭の変位は数%だが、スマートフォン画面でその振幅では数えられず、
> 実測モードが機能しない。視認性を優先し、パターン間の相対関係（浅い/深い）を
> 保ったまま拡大している。立位の胸郭は高さ 44px なので、振幅 1.12 で上端が約 5px、
> 1.18 で約 8px 持ち上がる。

### 波形

吸気 40% : 呼気 60%（I:E ≒ 1:1.5）の非対称波形とする。
左右対称の正弦波は生理学的に不自然で、呼吸の視認性も落ちる。

```css
@keyframes breathe {
  0%   { transform: scaleY(1); }
  40%  { transform: scaleY(var(--breath-amp)); }  /* 吸気 */
  100% { transform: scaleY(1); }                  /* 呼気 */
}
```

`transform-origin` を横隔膜位置に置き、`scaleY` とわずかな `translateY` で動かす。

## 5. SVG の契約

`components/patients/` の全イラストが従う。

```tsx
<g className="chest" style={{ animationDuration: `${cycleSeconds}s` }}>
```

- `illustrationId` と `canWalk` の対応は `domain/illustrations.ts` を正とする
- `apneic` の症例には `animationDuration` を設定せず、`chest` クラスも付けない
- `aria-label` には**答えを漏らさない**（SPEC §5.3）。呼吸の有無も漏らさないこと
- **四肢を胸郭に重ねない。** 動くのは胸郭だけなので、腕が被ると呼吸の動きが隠れて
  数えられなくなる。見た目の問題ではなく実測モードの機能要件である。
  特に胸郭の**上端**は最も変位する辺なので、肩関節をその高さから外す
- **胸郭は最大振幅で膨らんでも頭部に食い込まない間隔を空ける。**
  立位は胸郭の高さ 44px・振幅 1.18 で上端が 8px 持ち上がるため、頭部との間に 10px 以上取る
- 頸部を描くと、胸郭の挙上が頸部との距離の変化として読み取りやすくなる
- **傾きは `.chest` の外側で与える**（`FigureParts.chestRotate`）。内側で回すと
  `.chest` のバウンディングボックスが回転後の軸平行外接矩形になり、
  `transform-origin: center bottom` が横隔膜ではなく最下の**角**を指す。
  さらに scaleY が体軸ではなく画面の縦方向に効き、膨らみがせん断する
- **四肢は `M`/`L` の折れ線だけで描く。** 曲線は制御点の外側を通り得るため、
  重なりの検査を数値で行えなくなる

### これらは目視ではなく機械で検査する

イラストが増えるほど、重なりを目で守り切れない。実際に一度、腕が胸郭に
被って呼吸が数えられない不具合を出している。

`tests/figureGeometry.spec.tsx` が描画結果の SVG から座標を読み取り、
全イラストについて次を検査する。

| 検査 | 内容 |
|---|---|
| 四肢 | 中心線が胸郭の**上半分＋挙上域**に入らない。輪郭が肩の付け根で辺にかかるのは正常なので中心線で判定する |
| 頭部 | 最大挙上（×1.18）した胸郭との間隔が 2px 以上 |
| 傾き | `.chest` 自身が変形されておらず、回転は外側の親にある |
| 髪 | 全種について、多角形の頂点が挙上後の胸郭から 2px 以上離れている |

髪は**頭部の上**に重ねて生え際を見せる（裏に敷くと「少し大きい頭」にしか見えず、
所見と取り違えられる。SPEC §3.4）。形は多角形で作る。曲線コマンドは制御点の
外側を通り得るため、座標から安全性を検証できなくなる。

体格の拡縮（SPEC §3.4）は**人物全体に一様に掛かる祖先の transform** である。
`.chest` は `transform-box: fill-box` なので `transform-origin: center bottom` は
**その要素自身のローカル座標系**で解決され、祖先の変形に影響されない。
一様な拡縮は内外の関係も変えないため、検査は等倍のまま行えばよい。
周期と振幅が体格によらず不変であることは `tests/appearance.spec.tsx` が確かめる。

下端は `transform-origin` なので変位しない。脚の付け根が底辺にかかるのは
正常であり、そこまで禁止すると描けるポーズがなくなる。

## 6. 計測 UI

**計測器は常時表示する。** 呼吸・CRT・脈拍を横3列に並べ、開く操作を挟まない。
爪床の色も脈の拍動も、傷病者を前にすれば常に目に入る情報である。

```
├─呼吸──┬─CRT──┬─脈拍───┤
│ 12.4s   │  ▐█▌   │   ◉     │
│ 約34/分  │ 残3.2s │ 118/分   │
│[数える] │[爪を押す]│[脈を数える]│
└────────┴───────┴─────────┘
```

呼吸セルに図を置かないのは、胸郭が上の傷病者イラストで動いているため。
同じ情報を二重に出すと、どちらを数えるのか迷わせる。

### 旧: 計数 UI

```
┌──────────────────────┐
│  [胸郭が上下するイラスト]   │
│ 「倒れて動かない」        │
├──────────────────────┤
│   経過 12.4 秒            │
│   タップ 7 回             │
│   → 約 34 回/分          │
│                          │
│  [ 呼吸を数える（タップ）]  │
│  [ 気道確保を行う ]        │  ← 全症例に表示（§3.1）
│  [ 数え終えた → 判定へ ]    │
└──────────────────────┘
```

- **観察時間は自由。** 利用者が納得するまで観察できる。強制窓は設けない
- **タップ計数は回答の前提条件にしない。** 数えずに判断してよい（計数は学習補助）
- 経過 3 秒未満（`MIN_ESTIMATE_MS`）は推定値を表示せず、経過時間のみ出す。
  短すぎる観察では推定値が過大になり誤解を招くため
- 経過時間は `performance.now()` 基準。10 問モードのタイマーとは別計測

### 学習モードのフィードバック

計数精度と区分判定を**分離して**提示する。

```
推定 34 回/分 ／ 実際 36 回/分（誤差 −2）
→ 数え値はずれましたが、「30 回以上」という判断は正しいです。
```

## 8. 非スコープ

- 呼吸音・胸郭の左右差（気胸など）の表現。一次トリアージの範囲を超える
- 実測モードでの ±1 境界値訓練（§2 のとおり物理的に成立しない）
- 声かけの自由入力。選択肢に絞るのは、何を尋ねるべきかの訓練を成立させるため
- GCS など意識レベルの段階評価。一次トリアージの範囲を超える
