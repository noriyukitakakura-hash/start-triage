# 呼吸数の実測モード（胸郭アニメーション + タップ計数）

- 文書バージョン: 0.1 / 2026-11-15
- 関連: `SPEC.md` §2.2, §2.3, §2.4, §3.3, §3.4, §4.4, §5.3

---

## 1. なぜ実測するのか

現場の START 法では呼吸数は数値で与えられない。傷病者の胸郭の動きを**見て数える**。
数値提示（`呼吸 32 回/分`）は閾値の暗記訓練にはなるが、現場で必要な
「見て判断する」技能を一切訓練できない。

そこで傷病者イラストの胸郭を呼吸数に応じてアニメーションさせ、
利用者がタップで実際に数えて判断する**実測モード**を設ける。

### 実測化で得られるもの

| 得られるもの | 内容 |
|---|---|
| 無呼吸の自然な提示 | **「胸郭が全く動かない」という現場そのままの手がかり**になる。`自発呼吸: なし` というテキストラベルの人工性が消える |
| 死戦期呼吸の認識 | 呼吸数 4〜9 回/分を、数えるのではなく**見てわかるパターン**として提示できる |
| 技能の分離採点 | 計数精度と区分判定を分けて採点でき、「数え値は 2 回ずれたが 30 回以上という判断は正しい」というフィードバックが返せる |

## 2. 設計の前提: 観察時間と分解能

観察して数える場合、判別できる分解能は観察時間で決まる。

| 観察時間 | 分解能 | 29 と 30 を判別できるか |
|---|---|---|
| 6 秒 × 10 | 10 回/分 | 不可 |
| 10 秒 × 6 | 6 回/分 | 不可 |
| 15 秒 × 4 | 4 回/分 | 不可 |
| 30 秒 × 2 | 2 回/分 | 不可 |
| 60 秒 | 1 回/分 | 可（ただし 1 回数え間違えると区分が反転する） |

**±1 の真の境界値（9/10・29/30）と実測は両立しない。**
1 症例に 60 秒必要となり、10 問チャレンジが純粋な計数作業 10 分になる上、
タイム計測が「数える忍耐」の測定に変質する。

### 結論: 2 つのモードは異なる技能を担う

| モード | 訓練する技能 | 呼吸数の提示 | 境界値 |
|---|---|---|---|
| **数値モード**（既定） | 閾値の正確な記憶（9/10・29/30 の線引き） | 数値 | 呼吸数・循環・意識で使う |
| **実測モード** | 現場の実務（見て「明らかに速い」と判断する） | アニメーション + タップ計数 | 循環・意識のみで使う |

どちらも必要な技能であり、片方が他方を代替しない。

### 判別マージン ±4 の根拠

実測モードでは呼吸数を判定閾値から **4 回以上**離す（`rrMargin = 4`）。
JP-FDMA（下限 9・上限 30）での値域は次のとおり。

| 帯 | 数値モード | 実測モード | 15 秒観察時の呼吸回数 |
|---|---|---|---|
| 該当（下限）→ I類 | 4–9 | **4–5** | 1.00 – 1.25 回 |
| 通過 | 10–29 | **14–25** | 3.50 – 6.25 回 |
| 該当（上限）→ I類 | 30–44 | **34–44** | 8.50 – 11.00 回 |

15 秒の観察で 3 帯が明確に分離し、**帯の間に 1 回以上の差がある**ため、
数え間違いが 1 回あっても区分が反転しない。

歩行可能な症例（III類）の軽症域も通過域との交差を取り、マージンを尊重する（14–20 回/分）。
歩行可能なら呼吸数は評価されないが、実測モードでは利用者が胸郭の動きを見てしまうため、
**どの症例であれ閾値付近の曖昧な値を提示してはならない。**

## 3. 実装上の必須事項

### 3.1 気道確保ボタンの存在が答えを漏らしてはならない

数値モードの仕様（SPEC §2.2）は「**自発呼吸なしの症例のみ**、回答前に気道確保ボタンを挟む」。
数値モードでは `呼吸数 0` が同時に表示されるため問題ないが、
実測モードでは**ボタンの有無が観察前に無呼吸であることを教えてしまう。**

→ **実測モードでは全症例に気道確保ボタンを表示する。**
自発呼吸がある症例で押した場合は「自発呼吸を確認。気道確保は不要」と返し、判定は変えない。
漏洩がなくなり、かつ実際の START 法の手順（呼吸を確認し、なければ気道確保）に忠実になる。

### 3.2 アニメーションは厳密に毎分 `respiratoryRate` 回でなければならない

利用者のタップ数が真の呼吸数と一致しなければ、**誤った数値を教えることになる。**

CSS `animation-duration: ${breathCycleSeconds(rr)}s` で駆動する。

- コンポジタ駆動のため周期が正確
- メインスレッドを占有せず、10 問モードの `performance.now()` 計測を妨げない
- `breathCycleSeconds(rr) × rr === 60` をテストで保証している

### 3.3 死戦期呼吸の不規則化は平均レートを保つこと

死戦期呼吸は不規則な喘ぎと長い休止で表現する必要があるが、
**不規則化しても平均レートは厳密に `rr` を保たなければならない。**

→ 1 ループに `GASPS_PER_LOOP`（= 3）回の呼吸を不均等な間隔で配置し、
ループ長を `GASPS_PER_LOOP × breathCycleSeconds(rr)` 秒とする。
これにより見た目は不規則でも平均レートは厳密に `rr` になる。

### 3.4 低呼吸数と無呼吸の判別

呼吸数 4〜5 回/分は 12〜15 秒に 1 回しか動かず、**計数では無呼吸と区別できない。**

→ **死戦期呼吸のパターン（深く不規則な喘ぎと長い休止）で判別させる。**
「動きがあるか／全くないか」が判断基準であり、これが現場の実技そのものである。
学習モードの解説で `explain.agonalNote` により明示的に補足する。

### 3.5 アクセシビリティ（必須）

動きだけで情報を伝えるのは WCAG 違反（SPEC §5.3）。

→ `prefers-reduced-motion: reduce` の場合、その症例の呼吸数提示を
**自動的に数値へフォールバック**し、フォールバックしたことを画面に表示する
（`observation.reducedMotionFallback`）。支援技術向けには常に数値を DOM に持たせる。

### 3.6 タイムの比較可能性

観察時間が支配的になるため、実測モードのタイムは数値モードと比較できない。

→ 自己ベストを**提示方式ごとに分けて保持**する（`bestTimeMs: { numeric, observed }`）。
X ポスト文にもモードを明記する（`share.observedMode`）。

## 4. 呼吸パターン

`domain/breathing.ts` の `breathingPatternOf()` が分類する。
パターンは**見た目の分類**であり、トリアージ判定の基準値とは別概念である
（判定は必ず `judge()` が `RuleProfile` で行う）。

| パターン | 条件 | 見た目 | 振幅 `--breath-amp` |
|---|---|---|---|
| `apneic` | 自発呼吸なし | **全く動かない**（静止そのものが手がかり） | アニメーションなし |
| `agonal` | 1–9 回/分 | 深く不規則な喘ぎ + 長い休止 | 1.09 |
| `normal` | 10–29 回/分 | 規則的 | 1.06 |
| `rapidShallow` | 30 回/分以上 | 浅く速い | 1.025 |

### 波形

吸気 40% : 呼気 60%（I:E ≒ 1:1.5）の非対称波形とする。
左右対称の正弦波は生理学的に不自然で、呼吸の視認性も落ちる。

```css
@keyframes breathe {
  0%   { transform: scaleY(1); }
  40%  { transform: scaleY(var(--breath-amp)); }  /* 吸気 */
  100% { transform: scaleY(1); }                  /* 呼気 */
}
```

`transform-origin` を横隔膜位置に置き、`scaleY` とわずかな `translateY` で動かす。

## 5. SVG の契約

`components/patients/` の 13 種すべてが従う。

```tsx
<g className="chest" style={{ animationDuration: `${cycleSeconds}s` }}>
```

- `illustrationId` と `canWalk` の対応は `domain/illustrations.ts` を正とする
- `apneic` の症例には `animationDuration` を設定せず、`chest` クラスも付けない
- `aria-label` には**答えを漏らさない**（SPEC §5.3）。呼吸の有無も漏らさないこと

## 6. 計数 UI

```
┌──────────────────────┐
│  [胸郭が上下するイラスト]   │
│ 「倒れて動かない」        │
├──────────────────────┤
│   経過 12.4 秒            │
│   タップ 7 回             │
│   → 約 34 回/分          │
│                          │
│  [ 呼吸を数える（タップ）]  │
│  [ 気道確保を行う ]        │  ← 全症例に表示（§3.1）
│  [ 数え終えた → 判定へ ]    │
└──────────────────────┘
```

- **観察時間は自由。** 利用者が納得するまで観察できる。強制窓は設けない
- **タップ計数は回答の前提条件にしない。** 数えずに判断してよい（計数は学習補助）
- 経過 3 秒未満（`MIN_ESTIMATE_MS`）は推定値を表示せず、経過時間のみ出す。
  短すぎる観察では推定値が過大になり誤解を招くため
- 経過時間は `performance.now()` 基準。10 問モードのタイマーとは別計測

### 学習モードのフィードバック

計数精度と区分判定を**分離して**提示する。

```
推定 34 回/分 ／ 実際 36 回/分（誤差 −2）
→ 数え値はずれましたが、「30 回以上」という判断は正しいです。
```

## 7. ドメイン API

```ts
// src/domain/breathing.ts
breathingPatternOf(c: TriageCase): BreathingPattern
breathCycleSeconds(rr: number): number          // 60 / rr
agonalLoopSeconds(rr: number): number           // GASPS_PER_LOOP × 周期
expectedBreathCount(rr: number, elapsedMs: number): number
estimateRate(taps: number, elapsedMs: number): number
isEstimateReliable(elapsedMs: number): boolean

// src/domain/generator.ts
generateCase({ target, rrMargin: 4 }, rng)      // 実測モード用の症例
generateQuizSet(rng, { rrMargin: 4 })           // 実測モードの10問セット
canUseBoundary(step, rrMargin)                  // 実測モードでは呼吸数が false になる

// src/lib/storage.ts
rrMarginFor(presentation): number               // 'observed' → 4
recordBestTime(presentation, timeMs): boolean   // 提示方式ごとに記録
```

`domain/judge.ts` は**変更しない**。`respiratoryRate` が真値であることは不変である。

## 8. 非スコープ

- CRT の実測化（爪を押して色が戻るまでを観察する）。同じ発想で可能だが v1 では行わない
- 呼吸音・胸郭の左右差（気胸など）の表現。一次トリアージの範囲を超える
- 実測モードでの ±1 境界値訓練（§2 のとおり物理的に成立しない）
